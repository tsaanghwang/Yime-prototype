# “的字结构 / 所字结构”构式部件

## 目标

这两类构式由规则生成，不能穷举为普通词条。处理器只消费统一来源库已有读音，把少量高复用中间节点
列为预制缓存候选；进入缓存不等于获得词汇身份，也不等于允许直接上屏。

正式策略为 `internal_data/construction_component_policy.json`，实现位于
`yime/input_model/construction_components.py`。

## 两个构式族

### 的字结构

```text
{base} + 的
```

- 核心原子是「的 / de5」；
- 固定词和固定表达由显式裁决覆盖，例如「有的」「真的」「似的」；
- 其余材料按半固定构式处理；
- 只有重复服务于更长读音、并通过 A/B 和运行回放者，才可进入 `component_only` 缓存。

### 所字结构

```text
所 + {predicate}
```

- 核心原子是「所 / suo3」；
- `{predicate}` 必须已有来源门禁合格读音；
- 「所以」等非所字构式由首音节读音和显式词汇裁决排除；
- 「所有」「所在」「所谓」等词汇化结果可以是 `display_and_component`，不能被构式规则降级；
- 人名、地名、机构名和领域词等来源分类不进入所字构式候选，避免把「所字镇」一类专名误拆；
- 其余可恢复结果按 `component_only_candidate` 或 `runtime_generated` 审查。

## 缓存门禁

候选首先必须：

1. 完整读音和各组成部分均来自来源库；
2. 字数不超过策略的核心组件上限；
3. 所有读音都能由更小部件恢复；
4. 不与固定词裁决冲突。

通过基础门禁后，依赖数只用于提出候选，不能直接批准。A/B 必须比较：

- 有无预制部件时的可恢复目标数；
- 最短分解部件数；
- BCC 加权的组合步数收益；
- 新增的最短切分歧义。

预制缓存必须减少足够多的组合步骤，并把同文同音的内部结构竞争控制在较低比例。
递归运行时的 `_prune_states` 按最终文本去重，因此同一个文本、同一个读音的不同
切分路径不会直接形成重复候选；这类竞争计入搜索成本，不等同于用户可见歧义。
当前门槛要求组合步数改善率至少 50%，结构竞争率不超过 10%。

## “似的”与“般的”：同族、分治

二者可以归入同一个上位构式族 `similative_de_construction`：

- `shi_de`：`{comparand_or_predicate} + 似的`，如“一阵风似的”“不存在似的”；
- `ban_de`：`{comparand} + 般的`，如“梦幻般的”“天使般的”。

这个归并描述的是语法和语义关系，不意味着二者必须采用相同缓存策略。真实来源
A/B 显示：

| 变体 | 更长读音 | 减少组合步骤 | 改善率 | 结构竞争 | 竞争率 | 决策 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 似的 | 213 | 173 | 81.22% | 18 | 8.45% | `display_and_component` |
| 般的 | 90 | 11 | 12.22% | 32 | 35.56% | `runtime_generated` |

所以“似的”保留为可直接显示的固定助词结构，也作为高复用组合部件；“般的”仍由
“般 + 的”或“X般 + 的”现场生成。两者语义基本相近，但分布生产力和缓存收益明显
不同，适合共享构式规则、分别作物化决策。

## “般的”评估结论

运行：

```powershell
.\venv312\Scripts\python.exe tools\evaluate_construction_components.py
```

输出包括：

- `candidate_plan.tsv`：两类构式候选、建议角色、复用指标和显式裁决；
- `report.json`：完整 A/B 证据；
- `report.md`：面向审阅的结论摘要。

真实来源 A/B 结果：

| 指标 | 结果 |
| --- | ---: |
| 包含「般的」的更长读音 | 90 |
| 有预制部件时可恢复 | 90 |
| 无预制部件时可恢复 | 90 |
| 最短分解减少部件数 | 11 |
| 总计减少部件数 | 11 |
| BCC 加权减少部件数 | 0 |
| 最短路径使用「般的」 | 43 |
| 新增最短切分歧义 | 32 |

结论：`do_not_prebuild_use_runtime_generation`。

「般的」带来的少量组合步数收益全部落在无 BCC 需求证据的目标上，同时为「一般的」「天使般的」
等材料增加大量等长切分。因此不把它预制进核心；保留「般」和「的」作为来源合格小部件，由
`X + 般 + 的` 或 `X般 + 的` 现场生成。该结论不把「般的」标为无效；它的直接候选迁移仍须通过
运行排序回放。

## 当前边界

现有 Rime 发布词典尚不能表达“只作组件、不直接上屏”。本处理器现阶段生成规划和评估证据，不直接
修改运行词典。后续接入 `component_only` 通道时，必须保证精确候选查询排除该角色，而递归预组合
查询仍能读取它。
